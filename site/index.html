A working discipline for coding agents.

Bearingkit is a protocol and skill set that makes an AI coding agent work like a disciplined senior team: classify the request before acting, propose only when the blast radius demands it, prove before claiming, and hand off cleanly at the end of every session.

Install for Claude Code View the source

The problem it solves

A capable agent left on defaults fails in a few predictable ways. Each one has a counterpart in the kit.

It edits before it understands

The protocol's router names the intent first and sends the request to the matching skill before any code is read or changed.

It says “done” without proof

Evidence rules: a skill pastes the command, test or measurement that shows the result, or says plainly that it was not measured.

It takes risky actions unasked

The autonomy gate splits work into ACT and COUNCIL; schema, auth, payments, data deletion and production stay behind a human decision.

It forgets between sessions

bk-close writes a handoff in two blocks, verified against git, so the next session starts from the record, not from memory.

How it works

One protocol loaded at session start, a set of focused skills it routes to, and agents for independent review.

The autonomy gate

Every request is classified before anything happens.

ACT  tests, refactors, docs, app-layer fixes, small changes inside an approved plan: do it, then report.

COUNCIL  migrations, auth, payments, data deletion, multi-module contracts, remote systems: propose, then wait.

A lifecycle with gates

Each step has its own skill and the evidence it must show.

spec→plan→build→test→review→ship→close

Hot paths get an independent reviewer agent before merge.

Installed once, active where you say

Install per machine, activate per project. A project you have not activated sees nothing of the kit: no protocol, no skill in the listing, no hook. Activation writes one entry in the host's own config file and nothing else.

One source, several hosts

Skills are written once in the Agent Skills format and installed into each host with that host's own command. Plain-language triggers work in English and Vietnamese.

The skills

Seventeen skills plus the protocol. Each is a short body with gates and the evidence it must paste, and references it reads only when needed.

bk-spec
Pin a request down before building: restate, edge cases, assumptions, requirements
bk-plan
A phased plan with exit criteria and the evidence each phase must show
bk-build
Execute a plan or a small change: scout first, minimal touch, migration safety
bk-test
Tests as the contract, TDD by default, rendered checks for UI
bk-debug
Root cause before any fix; council after three failed attempts
bk-review
Review a diff before push: bugs, hot-path risk, untested claims
bk-ship
Finish done work: guardrails, secret scan, conventional commit, PR body
bk-close
End a session with a handoff verified against git
bk-audit
An investigation that ends in one verdict and the options rejected
bk-next
The next step, from the real repository state: git, plans, handoff
bk-design
Design with a point of view, critiqued before it is built
bk-setup
Make a project ready for agents on every host the owner uses
bk-ops
Deploys and infrastructure with a way back; incidents read-only first
bk-db
Database performance from the query plan; index changes with a way back
bk-perf
Measure, then optimize: every number with its method
bk-map
Map a codebase with file:line anchors: entry points, flows, rules, risks
bk-research
Outside sources and tool choices, every claim cited with a confidence

How claims are made. Each skill is distilled from named open-source skills and judged against those sources — the same task, fixture, model and host, run with the kit and with the sources as they ship. Where that comparison has not been run, nothing here says the kit is better. Results that did not replicate are recorded as such.

Install

Claude Code installs the kit as a plugin, once per machine; then you switch it on per project.

# Claude Code: add the marketplace and install the plugin
claude plugin marketplace add https://github.com/tuyenht/Bearingkit
claude plugin install bearingkit@bearingkit

# From a checkout: activate in a project, check what is on
cd <your project>
node <checkout>/bin/bearingkit.cjs activate
node <checkout>/bin/bearingkit.cjs status

The npm package is not published yet, so the command is the checkout's own entry point for now. Antigravity, uninstall and the per-host details: docs/hosts.md.
