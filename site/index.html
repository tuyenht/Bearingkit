One set of rules for my AI coding agents

Bearingkit is a protocol and 17 skills for Claude Code and Antigravity. With it installed, the agent works out which step a request belongs to, asks me before it touches migrations, auth, payments or production, and shows test output before it calls a job done. I wrote it for my own work, and it takes requests in English or Vietnamese.

Why I made it

I had several skill packs installed at once: Superpowers, Anthropic's official plugins, a TDD pack, a review pack. Each was good at something, but together they got in each other's way. Two skills would pick up the same request with different rules, all of their descriptions sat in the context before I typed anything, and none of it carried over when I moved a project to Antigravity.

So I read them properly, with my agents doing much of the legwork. That came to 23 sources, and 1,295 skills, commands, agents and rule files from 22 of them, listed one by one and each marked to adapt, keep only as an idea, or drop. Where two sources disagreed, I kept one rule and wrote down why. The result is one protocol that loads in every session and 17 skills it routes to.

Every adapted file names its source, and PROVENANCE.md lists what is borrowed and what I wrote. Bearingkit is an independent project, not affiliated with or endorsed by Anthropic or Google.

When it acts and when it asks

Each skill hands off to the next one. The chain stops whenever a change needs my decision.

specplanbuildtestreviewshipclose stops at COUNCIL
ACT: does it, then reports

Tests, refactors that keep behavior, docs, app-layer fixes, small changes inside a plan I approved.

COUNCIL: proposes, then waits

Schema and migrations, auth, permissions, payments, deleting data, contracts between modules, remote or production systems. If the agent isn't sure which side a change is on, it treats it as COUNCIL.

Evidence before “done”

A claim needs a file:line or is marked unverified. A number needs its method or says “not measured”. A passing check only counts once it has been shown it can fail.

Bugs

Root cause before any fix. After three failed attempts the agent stops and asks.

A second look at hot paths

Auth, payments, uploads, tenant scoping, migrations and outside APIs get an independent review before push, ideally by a different model.

Handoffs

bk-close writes a handoff and checks it against git. The next session, bk-next starts from git and that handoff, not from memory.

What you can say to it

Plain requests. These come from the activation test set, each with the skill it should open. You can still call a skill by name.

  • Add CSV export to the invoices page.bk-spec
  • Uploads over 5 MB silently disappear.bk-debug
  • Is this branch safe to merge?bk-review
  • The error-rate alert on checkout fired ten minutes ago. Find out what is going on.bk-ops
  • Where were we, and what should I pick up next?bk-next
  • Wrap up the session and write the handoff for the next one.bk-close

The set has 96 prompts, 44 of them in Vietnamese. On its 60-prompt core, precision and recall are at least 0.9 on both Claude Code and Antigravity 2.0 (Claude Code, 2026-09-16: recall 0.958, precision 1.000). It only checks that the right skill opens. I haven't measured the code that comes after.

The 17 skills

Each is a short instruction file, most with reference files it opens only when needed. Before its first edit, bk-build also reads a rule file for the project's stack: TypeScript/React, Kotlin, SQL, Node, Python, PHP/Laravel or Shell.

bk-spec
Pin a request down: restate it, find edge cases, list assumptions
bk-plan
Phases, each with exit criteria and the evidence it must show
bk-build
Carry out a plan or a small change, touching as little as possible
bk-test
Test first by default; check UI in the rendered result
bk-debug
Root cause before any fix; ask after three failed attempts
bk-review
Bugs, hot-path risk and untested claims, before push
bk-ship
Project checks and a secret scan, then the commit and PR text
bk-close
End a session with a handoff checked against git
bk-next
Pick the next step from git, plans and the last handoff
bk-audit
Investigate, then one verdict and the options rejected
bk-design
Design an interface and critique it before building
bk-map
Map an unfamiliar codebase with file:line anchors
bk-research
Outside sources and tool choices, with a confidence level per claim
bk-ops
Deploys and infrastructure changes with a way back; incidents read-only first
bk-db
Database performance from the query plan; index changes with a way back
bk-perf
Measure, then optimize, with the method next to every number
bk-setup
Get a repository ready for agents on every tool you use

Status

Started in September 2026. Pre-release, developed in the open. The figures here come from docs/status.md and the design files in docs/specs, which record how each was measured.

Works today

  • 17 skills plus the protocol, on Claude Code and Antigravity 2.0
  • Routing in English and Vietnamese, as measured above
  • Per-project activation and seven stack rule files
  • 233 automated tests in the repository

Not shown yet

  • That it beats its sources. I compared skills one at a time with the packs they came from (same task, starting code, model and agent; small samples). Most showed no clear difference; one planning task with one model favored the kit.
  • That it saves tokens. Where I recorded cost, the kit used about 1.3 to 3 times what its sources did.
  • Whether anyone besides me will find it useful.

Next

  • The kit against a hand-assembled stack of packs on the same tasks: wrong activations, defects, tokens (proposal, not run yet)
  • Trap tasks (a migration, a deletion, a production push): how often the agent acts without asking, with and without the kit
  • Acceptance on Gemini CLI, Cursor and Codex

Install

Once per machine, then activate it in each project that should use it.

# Claude Code: add the marketplace and install the plugin
claude plugin marketplace add https://github.com/tuyenht/Bearingkit
claude plugin install bearingkit@bearingkit

# Antigravity: install once per machine (run from a clone of the repo)
node <checkout>/bin/bearingkit.cjs install --host antigravity

# Any agent: activate in a project, then check what is active
cd <your project>
node <checkout>/bin/bearingkit.cjs activate
node <checkout>/bin/bearingkit.cjs status

There is no npm package yet, so the command line runs from a local clone (<checkout>). Per-agent details and uninstalling: docs/hosts.md.
