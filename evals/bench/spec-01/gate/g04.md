# Reopening tickets from the portal

The owner wants customers to be able to bring a closed ticket back within two weeks, with the assigned agent told about it. Looking at the project, this is not a small addition. The glossary is explicit that closed means finished for good, and that a customer who comes back after that starts a new ticket; what can be brought back is a resolved ticket. The request therefore contradicts the documented lifecycle, and the owner needs to decide whether the lifecycle changes or whether the request was really about resolved tickets.

There is a second problem with the two weeks. The nightly purge removes the conversation of a closed ticket seven days after it closed, so in the second week of the requested 14 days there would be nothing left to reopen but a subject line.

The mechanics are mostly there already. Agents reopen resolved tickets through `reopenTicket`, and a customer's answer on a resolved ticket also puts it back to open. Whatever is decided should build on those rather than introduce a third path.

The SLA due time is set when a ticket is created; the current reopen path does not touch it.

I would implement this as a portal function next to `reply`, with a test for each acceptance criterion: a resolved ticket becomes open, the assignee gets one email, a closed ticket is refused with the existing message.
