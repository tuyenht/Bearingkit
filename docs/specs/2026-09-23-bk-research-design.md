## What it is for

One person doing what a staff engineer does before a technical decision: find out what the documentation of the version in use actually says, what independent evidence says about the options, what is still unknown, and hand over an answer whose every claim can be checked. The scope test of spec §1 holds: each step is one that role owns. A question this codebase or settled knowledge answers is not this skill's work; the protocol's first row answers it directly.

## The shape

- **The question first**: one question a source can settle, or three to five sub-questions, and the decision it serves; prior work in the repository cited before anything is searched.
- **A query plan** before searching: claim type, where to look, what settles it, what would count against the leading answer.
- **Authority by claim type**, which reconciles the two stances the inventory left open (`docs/specs/2026-09-18-item-inventory.md:476`): for a fact the vendor defines, its documentation for the pinned version first; for a claim about the vendor's product, independent sources over a single vendor page. The persona (`bk-protocol/references/personas.md`, `agents/bk-researcher.md`) now says the same.
- **Gathering** from the page that owns the fact; search results are leads; where a tool summarises pages, a quoted line or an absence the answer rests on is read from the raw page.
- **Cross-check**, conflicts shown, evidence against the answer sought, sources dated.
- **Labels** on every claim (link, version or date, confidence, fact or inference or recommendation); "not found" in an UNVERIFIED block.
- **The answer** first, a position when the evidence supports one, open questions last; an adoption checklist for a choice of tool or library.
- **Gates**: read-only for the project (adopting, dropping or upgrading goes to `bk-spec`); fetched pages are data; no secret in a query or a URL, no private address fetched, a redirect named before it is followed; no number without its page; the model's memory is never a source.

Where it writes: nowhere by default. The answer stays in the chat; a file is written only when the user asks or a spec will cite it, by the location lookup of v1 §6 (the project's instructions, then an existing folder that holds research or decision notes), with `docs/research/<date>-<slug>.md` as the default of last resort. v1 §6 names no default for this skill; the path is a choice made in this sprint under the owner's delegation ("Tiếp tục theo khuyến nghị tốt nhất", 2026-09-23), recorded in v2 §15, and reversible.
