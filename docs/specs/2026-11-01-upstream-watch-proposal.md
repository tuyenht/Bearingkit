## 2. The two jobs

### Job A. Drift of the 23 listed sources since their locked commits

**What can be automated, with a measurement.**

1. *Did the remote move?* `git ls-remote <repo> HEAD` against `sha` (`reviewed.sha` once that field exists, §3). Measured: one sequential pass over the 23 sources took 27.2 s (3.6 s for the slowest, claudekit-engineer; about 1 s for the rest). Result that day: 5 sources unchanged, 18 moved. A moved HEAD alone is weak evidence: 18 of 23 moved, and only 5 sources have tracked files (`tracked` is non-empty for superpowers, claude-plugins-official, karpathy-skills, mattpocock/skills, anthropics/skills).
2. *Did a file we adapted from change?* Shallow-fetch the locked sha and the new HEAD into a scratch repository, then `git diff --name-status <sha> <head> -- <tracked paths>`. Measured on 3 of the 5 sources with tracked files, into a scratch folder outside the repository:

   | Source | Fetch and diff | Scratch `.git` | Tracked paths | Changed |
   |---|---|---|---|---|
   | obra/superpowers | 3.5 s | 856 KB | 36 | 32 (27 modified, 5 deleted) |
   | mattpocock/skills | 3.4 s | 488 KB | 4 | 4 (modified) |
   | anthropics/claude-plugins-official | 6.0 s | 7,936 KB | 23 | 7 (modified) |

   The other two sources with tracked files (karpathy-skills, anthropics/skills) were not measured.
3. *Tag-locked sources* (superpowers `v5.1.0`, jeffallan `0.4.14`, Antigravity-Core `5.0.1`): the useful question is "is there a newer tag", from `git ls-remote --tags`. For superpowers that output on 2026-11-01 lists tags up to `v7.0.1`, and a diff of `v5.1.0`'s sha against the default branch touched 86 files under `skills/`, `hooks/` and `README.md` (`git diff --stat`). Whether the default branch equals the latest tag was not checked.
4. *Licence change, renamed or deleted repository, new top-level skill folder*: a path-level diff of the repository root (names only) would catch, for fetched sources only, a `LICENSE` file appearing, disappearing or changing. Not measured.

**What cannot be automated.** Whether a change matters. A changed tracked file says "look", not "absorb". That judgment is `bk-audit`'s (§3, Design A, "How a delta reaches a decision"), and the kit's rule is that "better than the source" is only ever claimed from a same-task comparison (AGENTS.md; v1 §17).

**Honest limits.** Two sources need special handling. Clean-room claudekit-engineer is a proprietary source whose text the kit must not absorb (`sources.json` mode "ideas-only clean-room"); `ls-remote` returned a sha for it on 2026-11-01 even though its note says the repository is private, and why that worked (stored credentials) was not investigated, so a machine without those credentials would see it as `auth` or `not-found` (which of the two depends on what git reports; not tested). The owner's Antigravity-Core is the owner's own repository and the kit supersedes it, so its "drift" is the owner's own work. Antigravity-Core's locked sha (1774280e) exists only locally; its public remote has only an older commit (`upstream/sources.json`, `local` field of that source). Design A cannot tell `base-missing` for it: it has no tracked files and is head-only, so it shows `moved-head-only` from `ls-remote`. The report carries a fixed note on its row, from `sources.json` `local`: locked sha not on the public remote. `base-missing` is reported only for a source that was fetched.

### Job B. What is new outside the list

**What can be automated.** A list of candidate repositories, not a list of recommendations. Measured: `gh search repos --topic claude-code-skills --limit 100` returned 100 repositories in 3.7 s; none of the 100 is in `sources.json`; 11 of them have no recognised licence key in the answer. The 100 is the cap that was asked for, not the number that exist, and one topic is one of many. From such a list a script can mechanically state: already a source or not, licence key, last push date, whether it ships a `SKILL.md`.

**What cannot be automated.** Whether a practice is worth adding, whether it is good, whether a missing licence means "unlicensed" or just "the API did not report one", and whether the page is honest. Ranking by popularity is not a quality signal and can be bought; the command should not rank. Text outside GitHub (host release notes, articles) is not covered. The host-drift watch is the other row of v2 §16 (`...v2-design.md:228`) and stays separate (§6 decision 7).

Honest summary: Job A is mostly automatable (the fact that something changed, which files, how many). Job B is automatable only as candidate collection; every decision is human or `bk-audit`.

## 3. Designs

All three keep the existing rule that nothing changes `skills/` or `sources.json` without a human-reviewed commit. They differ in how much the command does.

### Design A (recommended): read-only report command, decisions stay in git

**Shape.** `node bin/bearingkit.cjs upstream-watch [--only <name>] [--discover] [--report-dir <folder>]` (default `docs/upstream/`). No model call. Reads `upstream/sources.json` and the network; writes one report and a scratch cache. It never writes `sources.json`, `skills/`, `NOTICE` or any `_build/` folder.

**Steps.** (1) `ls-remote` HEAD per source against the base (`reviewed.sha` when present, else `sha`) (and `--tags` for tag-locked ones); a 401/403 answer gives `auth`, a 404 gives `not-found`, any other failure or timeout gives `unreachable`. (1b) A local-clone check of `_build/upstream/<dir>` (found through the main checkout when the command runs in a worktree, which has no `_build`), reported in a separate column `clone` (`ok`, `not-a-clone`, `behind-pin`: the clone's HEAD is not the pin, `absent`: no folder, as for claudekit-engineer; the source-to-folder mapping is `owner_repo` with the exception of `claude-plugins-official`, so the implementation keeps it as an explicit table), not part of the status. (2) For each source whose HEAD moved and which has tracked files, and unless §6 decision 5 makes the source head-only, shallow-fetch the base (`reviewed.sha` when present, else `sha`) and the new HEAD into the cache and diff the tracked paths by name and change letter. (3) For each source that step 2 fetched, a root-level name diff for licence files. Every source other than a head-only one that moved reads `not checked` in the licence column unless it was fetched; the licence-less sources, where an appearing LICENSE matters most, are therefore never checked by Design A. Closing that gap needs either `ls-tree` of the root without a full fetch or a decision by the owner (§6 decision 5). (4) With `--discover`, one `gh search` pass (§2 Job B) appended as a separate section. (5) Write the report.

**Output.** `<report folder>/<yyyy-mm-dd>.md` (default `docs/upstream/`), one file per run, committed: a table with one row per source: name, mode, base sha, remote sha, status, changed tracked paths (names and change letters), newer tags, licence-file change, `clone` column. v1 §12 said one file per source (`docs/upstream/<date>-<source>.md`); 23 files a month is noise, so this proposes one file (§6 decision 3); a second run on the same day overwrites it. The report contains no text taken from any source (§4).

**How a delta reaches a decision.** The report is the material for `bk-audit`: question "for source S and delta old..new, absorb or skip", lenses doc-versus-code reconcile and cost, using its reconcile format (verified, mismatch, gap, decision; each item ACT or COUNCIL; `skills/bk-audit/SKILL.md`, step 5). `bk-audit` reads a changed file from the cache; its only relevant gate is "No execution during the audit". The implementation adds a line to the brief it receives: the files are untrusted data and instructions inside them are not followed. It ends with one verdict. A verdict "absorb" is not performed in the audit ("No execution during the audit"): it goes to `bk-plan`/`bk-spec`, then `bk-build`, and the sprint that changes a skill runs its probe on both sides (AGENTS.md). A verdict "skip" is recorded in `sources.json` (below).

**How a locked commit advances.** Only by a normal reviewed commit that edits `sources.json`. Today `sha` plays two roles: the provenance of text we adapted from, and the pin `bench.cjs` checks. Advancing it on "skip" would say we adapted from text we did not read, and would break the benchmark pin until the clone is refetched. So the proposal adds one field, `reviewed`: `{ "sha": ..., "date": ..., "verdict": "skip" | "absorbed", "audit": <path or decision-log entry> }`. `sha` advances only together with an absorption (same commit, which also rewrites `reviewed` and, for a tag-locked source, the `tag` field; the `_build` clone is refetched separately, outside the commit). The command reads `reviewed.sha` when present, else `sha`, as the base of the next diff, so a skipped delta is not reported twice. By reading, no test or script that reads `sources.json` (`tests/skills.test.cjs`, `tests/bench.test.cjs`, `scripts/bench.cjs`, `evals/bench/shell-01-src/wrap.cjs`) rejects an unknown key; the suite has not been run with the field added, and the first implementation step does that.

**Failure and offline.** Each source gets one status: `same`, `moved`, `moved-head-only` (policy: no paths fetched, changed paths unknown), `unreachable`, `auth`, `not-found`, `base-missing` (the locked sha is not on the remote), `skipped-by-policy`. A source the command could not check is never reported as `same` (the rule `doctor` already follows, v1 §13: it "never reports OK for a check it could not run"). Per-source timeout 60 s (a default; tests inject a shorter value, see test 12). Exit code: 0 when every source was checked; 2 when the report was written but at least one source is not `same`, `moved` or `moved-head-only`; 1 when a prerequisite is missing (no `git`, unreadable `sources.json`, unwritable report folder). Offline: all 23 rows `unreachable`, the report says so, exit 2, nothing else changes.

**Reads and writes.** Reads: `upstream/sources.json`; the network (`git` over https to the `repo` URL, `gh` only with `--discover`); `_build/upstream/<dir>` read-only, only to check that each clone is at the pin before the owner advances `sha` (what `bench.cjs` needs). Writes: `<report folder>/<date>.md` (default `docs/upstream/`); a scratch cache under `~/.bearingkit/state/upstream-cache/` (the kit's own state folder, the same place the machine lock lives; nothing under `~/.claude` or `~/.gemini`). Never: `_build/`, `skills/`, `sources.json`.

**Cost.** Time: measured in §2, about 27 s for the cheap pass plus about 3.4 to 6 s per source with tracked files that moved; under decision 5(a) the three fetched sources are the three measured; with option (b) the other two add unmeasured cases. Disk: 488 KB to 7,936 KB of scratch per measured source. Tokens: the command makes no model call; the audit that reads a report: chưa đo. Report size: chưa đo. Money: none (public repositories, no paid API; `gh` rate limits for `--discover` were not measured).

**Critique.** For: small, deterministic, testable offline with local fixture repositories, and keeps every decision where it is today. Against: it only reports; the monthly cadence still needs someone to run it (§6 decision 6), and Job B stays a weak, human-judged list. The new `reviewed` field is a schema change to provenance and is the owner's call (§6 decision 2).

### Design B: the command also decides and advances

**Shape.** Same fetch, plus `--accept <name>` which rewrites `sha` in `sources.json` and refreshes the `_build` clone, plus an unattended scheduled run that calls a model per delta to draft an absorb/skip verdict and opens a branch.

**Critique.** Rejected. (1) It writes provenance without a human reading the delta, so a source can be "current" while nothing was reviewed: the exact failure `upstream-watch` is meant to prevent. (2) It breaks the bench pin as a side effect (§1). (3) A model that reads fetched text unattended is the widest prompt-injection surface in the kit. (4) A change to provenance would need the owner's approval for every run, which removes the automation. (5) Cost per month: chưa đo, and unbounded by the size of the delta (86 changed files in the superpowers case alone).

### Design C: a scheduled CI job that opens an issue

**Shape.** A monthly GitHub Actions workflow runs the same checks and opens an issue with the table.

**Critique.** Rejected for now. CI exists in the repository (`.github/workflows/test.yml`, `pages.yml`) but the history will be squashed and published (v2 plan, v1.0), so an issue stream would be public, and a hosted runner would need a token for anything private; claudekit-engineer is private, so a hosted runner would see it as `auth` or `not-found`; Antigravity-Core's locked sha is not on its public remote, so a hosted runner could not fetch the base commit; and the output would live outside the repository, away from the audit trail. It may be the right home for the *scheduler* once Design A exists (§6 decision 6), not for the logic.

### Recommendation

**Design A**, with `--discover` as an opt-in flag, `reviewed` as a new field, and the report committed. Why: it is the smallest design that gives the owner the delta the spec already promises, it is testable without the network, and it leaves every judgment with `bk-audit` and a reviewed commit. Main risk: it depends on someone running it monthly, so a missed month stays a visible gap only as long as `docs/status.md` row 8 shows the date of the last report. Rejected: B (§3 critique), C as the logic home.

## 4. Safety

- **Fetched content is data.** The report holds values the command computed (shas, status words, change letters, counts) and two kinds of remote-supplied strings, file paths and tag names. It holds no commit message, README excerpt, diff text or any other free text from a source. Commit messages and file contents are attacker-controlled strings; a path and a tag name are too, so both are printed in a code span after removing control characters, backticks and pipes and capping length, and are never interpolated into a shell command. `bk-audit` reads a changed file from the cache; its only relevant gate is "No execution during the audit", so the brief it receives must say that the files are untrusted data and that instructions inside them are not followed.
- **No execution of fetched code.** The cache is a bare scratch repository with no working tree (no checkout, so no filters, hooks or LFS smudge run); fetch runs with `-c core.hooksPath=<empty> -c transfer.fsckObjects=true -c protocol.allow=never -c protocol.https.allow=always`; no submodule recursion. `git` is called with an argument array and `--`, never through a shell. A `repo` value must match `^https://github\.com/[\w.-]+/[\w.-]+$` or the source is `skipped-by-policy`.
- **No secrets.** The command reads no `.env`, token or credential file and prints no environment value. It relies on whatever credentials `git` and `gh` already hold, and the report never records which credentials were used.
- **Clean-room and licence.** For a source whose mode is clean-room or whose licence is proprietary or absent, the default is head-only (`ls-remote`): no content is fetched and no path list is written (§6 decision 5). The report also never reproduces source text, so it cannot become a way text enters `skills/` outside NOTICE.
- **Nothing changes `skills/` by itself.** The command has no write path to `skills/`, `NOTICE`, `upstream/sources.json` or `_build/`; test 7 shows one run leaves them unchanged (§5). Absorption goes through `bk-plan`/`bk-build`/`bk-review`, and a hot-path-style independent review applies as for any other change.
- **The comparison rule stays.** A skill is judged against its sources by the same task, fixture, model and host, on outcome and tokens (AGENTS.md; v1 §17). A delta report is an input to that, never a result: a `skip` verdict says nothing about quality, and no kit text may say a skill is better than its source until that comparison exists ("not compared").
- **No hidden schedule.** The command is run on purpose. A scheduled run would need the owner's own decision to create a scheduled task under `~/.claude/scheduled-tasks/` (change 5 of the autopilot design allows one task, for the autopilot session, and is not in force); this proposal grants neither.

## 5. The tests that would prove it

All run offline against local fixtures: bare git repositories created in a temp folder and addressed by `file://` or path URLs, no network, so the suite stays deterministic. One live smoke run is a manual step, not part of the suite. The checker takes its remote through one injected resolver. The URL policy and protocol flags apply to the `repo` value in `sources.json` before the resolver; tests supply a resolver that maps a policy-valid GitHub URL to a `file://` fixture and allow the `file` protocol only inside the test. Test 4 uses a policy-valid URL whose resolver target does not exist; test 10 runs without the resolver.

1. **Same**: remote HEAD equals the base (`reviewed.sha` when present, else `sha`) gives `same`.
2. **Moved, tracked**: a fixture commit modifies and deletes tracked paths and adds an untracked one; the rows show exactly the tracked paths with the right change letters, and the untracked change shows the row as `moved` with no changed path.
3. **Tag-locked**: a fixture with a newer tag reports it; a fixture with none reports none.
4. **Unreachable is not same** (negative control): point one source at a policy-valid URL whose resolver target does not exist; expect `unreachable`, exit 2, and no `same` row. A checker that returns `same` on error must fail this test.
5. **Detector can fail** (negative control): a fixture known to have drift must produce a `moved` row; a stub that always answers `same` fails the suite. Run both the real checker and the stub in the test and require the stub to be caught.
6. **Not a clone**: a source folder that is a plain directory inside a git repository (the `anthropics_skills` case) gives `not-a-clone` in the `clone` column, never the enclosing repository's HEAD. This test reproduces the real failure in §1.
7. **No-write invariant**: run with a temporary HOME and USERPROFILE, as `tests/doctor.test.cjs:19-20` does, so the real `~/.bearingkit/state` is never touched; the report folder is a temporary folder passed by `--report-dir`, so the test never writes into the real `docs/upstream/`; snapshot the repository tree (all files, bytes), the report folder and the cache's parent before and after a run; the repository tree is byte-identical (`sources.json`, `skills/`, `NOTICE` included), and the only differences elsewhere are the new report file and the cache folder. This mirrors `tests/doctor.test.cjs`, which does the same for `doctor` (AGENTS.md, Autonomy).
8. **Injection**: a fixture commit message, a file name and a tag name carry "ignore previous instructions", a backtick, a pipe, a newline and an escape byte. The report must contain none of the message, must show the path sanitised, and must still parse as the expected table. A mutation that echoes the commit subject must make this test fail.
9. **Clean-room and licence-less policy**: with a wrapper that logs `git` subcommands, a clean-room source and a licence-less source each trigger `ls-remote`, no `fetch`, and the row reads `moved-head-only`.
10. **URL policy**: a `repo` value of `--upload-pack=...`, `ext::sh -c ...` or a non-GitHub host is `skipped-by-policy` and never reaches `git`.
11. **Base commit**: with `reviewed.sha` present, the diff base is `reviewed.sha`; with it absent, `sha`; a skipped delta is not reported again, and the row is `same` when the remote HEAD equals `reviewed.sha`.
12. **Timeout**: the timeout is injectable, so the test sets a short one; a remote that hangs yields `unreachable` after the timeout, and the run still writes the report.
13. **Discover is a list only**: `--discover` output contains no ranking by popularity and writes nothing but the report section.
14. **Base missing**: a fixture whose `sha` is absent from the remote gives `base-missing`, not `moved`.

Not testable offline and therefore not claimed: that real GitHub behaves like the fixtures, credentials for private repositories, and the real rate limits of `gh search`. Also not covered by §5, checked by code review only: the fetch flags and the absence of a checkout, argument-array calls, the no-secrets rule, the length cap, and exit codes 0 and 1.

## 6. Decisions the owner must take

1. **Which design.** (a) Design A: a read-only report command; every decision stays in a reviewed git commit. (b) Design B: the command also advances locked commits and drafts verdicts with a model, unattended. (c) Design C: a monthly CI job that opens an issue. Recommended: (a).
2. **How a skipped delta is recorded.** (a) Add a field `reviewed` to each source in `sources.json` (sha, date, verdict, pointer to the audit), keep `sha` as the provenance of the adapted text and the benchmark pin, and advance `sha` only with an absorption. (b) Advance `sha` on every decision, including skip; the benchmark clones must then be refetched each time and provenance no longer says what was adapted from. Recommended: (a).
3. **Where the report goes.** (a) One committed file per run, `docs/upstream/<date>.md`. (b) One committed file per source per run, as v1 §12 wrote. (c) A report that is not committed, with only a one-line "last run" date in `docs/status.md`. Recommended: (a).
4. **Whether discovery of new sources ships with it.** (a) A `--discover` flag that lists candidates (name, licence key, last push, whether already a source) and never adds one; default off. (b) Drift only now; discovery stays by hand until the drift report has run for a few months. (c) Never automate discovery. Recommended: (a).
5. **Clean-room and licence-less sources.** (a) Head-only: the command checks whether the remote moved and fetches nothing, so no path list is written for them. (b) Treat them like every other source and list changed paths; the changed path names of the private claudekit-engineer would then be written into a committed report. The affected sources are the clean-room, proprietary or licence-less ones in `sources.json`; counting them by rule needs the owner's definition of "licence-less", and the field that marks a source head-only is part of this decision: `mode` and the prose `license` text do not carry it reliably, so the implementation needs a flag in `sources.json` or a list in the command. Of the five sources with tracked paths, two (karpathy-skills, anthropics/skills) have no top-level licence; under option (a) they never get a path diff. Recommended: (a).
6. **Who runs it and how often.** (a) The owner, or a session the owner starts, by hand at least monthly; `docs/status.md` row 8 shows the date of the last report so a missed month is visible. (b) A scheduled task, which needs the owner's own decision to create one under `~/.claude/scheduled-tasks/` (change 5 of the autopilot design is not in force and covers the autopilot session only). (c) CI, which would see the private claudekit-engineer as `auth` or `not-found` and cannot fetch Antigravity-Core's locked sha, which is not on its public remote. Recommended: (a).
7. **Host-drift watch.** (a) Stays a separate job (v2 §16, the second drift row), run by hand on a host update. (b) Is merged into this command. Recommended: (a); this proposal covers sources only.
8. **Safe cache location.** (a) `~/.bearingkit/state/upstream-cache/`, the kit's own state folder. (b) A gitignored folder inside the repository (`_build/`), which a worktree does not have. Recommended: (a).
