### Added (2026-09-16)
- `detect-stack` recognises Terraform: a directory with `*.tf` files or a `.terraform.lock.hcl` reports `languages: ["terraform"]`, with `terraform fmt -check -recursive`, `terraform validate` and, when `.tflint.hcl` exists, `tflint` as guardrails. Provider majors (AWS, Google, AzureRM, Kubernetes, Helm) come from the lock file, which records what was installed, rather than from the constraint in `required_providers`. `plan`, `apply` and `init` are never guardrails — the first two read remote state with real credentials, the third downloads — and a test holds that. Like every detector it reads the directory it is given, so a multi-root layout is recognised from inside an environment directory, not from the repository top. Drift item (h).
- The stack profile carries `notes`: preconditions a guardrail has that its command line cannot say, always present, empty for most stacks. Terraform is the first user, found by the re-check of the Terraform work itself: on a fresh clone `terraform validate` fails with an error that says to run `terraform init`, and a plain init configures the remote backend. The note names the preparation that never touches the backend (`terraform init -backend=false`, and `tflint --init` when tflint is a guardrail) and says a plain init is COUNCIL. The acting agent reads the profile, not the detector's comments, so that is where the warning has to be.
- `detect-stack` names the guardrails it used to leave to each project: ESLint and Prettier when called directly, black, mypy or pyright, `go vet` and `golangci-lint`, `cargo fmt --check`, and the `ktlintCheck` and `detekt` Gradle tasks. Each tool is called in the form that fails — `eslint --max-warnings 0`, `prettier --check`, never a `format` script, which usually writes. A project's own `lint` script wins over a direct ESLint call and Biome displaces Prettier; that precedence was seen failing under a deliberately naive version before the real one was written. `gofmt` is left out on purpose: `gofmt -l` lists the files it would change and still exits 0. None of these tools is installed on the machine that wrote this, so their exit behaviour is taken from their documentation, not from a run. Drift item (o).
- `references/stacks/index.md` had a `c` or `cpp` row while claiming to be checked against real output; the detector reports `c-cpp`. Every row was re-run against every fixture, the row is corrected, and rows now say plainly which languages the profile reports that have no stack file (`java`, `go`, `rust`, `csharp`, `terraform`) and that shell, like SQL, is opened by subject matter. `kotlin.md` and `typescript-react.md` describe the new guardrails instead of the old gaps.
