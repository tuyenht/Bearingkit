# Changelog

All notable changes to Bearingkit. The format follows Keep a Changelog; versions follow semver. This is the single changelog.

## Unreleased

### Changed (v2 restructure, 2026-09-11; spec `docs/specs/2026-09-11-bearingkit-v2-design.md`)
- The kit takes the shape of obra/superpowers: `skills/` at the repository root in the Agent Skills format, one manifest per host (`.claude-plugin/`, `.codex-plugin/`, `.cursor-plugin/`, `gemini-extension.json` with `GEMINI.md`, `.antigravity/`), one bootstrap per host (a SessionStart hook for Claude Code, Cursor, Copilot CLI and Factory Droid in `hooks/`; a `GEMINI.md` import for Gemini CLI; an always-on rule inside the Antigravity plugin copy). Each host installs the kit with its own command (`docs/hosts.md`).
- `core/AGENTS.md` and `core/rules/security-baseline.md` became the body of `skills/bk-protocol/SKILL.md`, printed at session start by `hooks/session-start.cjs`; skills fetch the stack profile with `scripts/detect-stack.cjs` instead of reading an injected block. Language guidance will live in `skills/bk-build/references/stacks/`.
- The four personas gained hand-written agent files under `agents/` (Claude Code, Cursor), paired with `personas.md` by a test.
- The evals runner loads the checkout with `claude --plugin-dir` by default (`--plugin-dir none` for baselines); the Antigravity runner arms against any existing plugin directory.
- Acceptance test passed on Claude Code 2.1.268 and on Antigravity 2.0 (2.12.2, Opus 4.6 thinking) on the day of the restructure (`docs/hosts.md`). The Antigravity copy carries the protocol plus the Antigravity host note (open `skills/<name>/SKILL.md` with `view_file` first); the first v2 copy had dropped the note and the feature prompt failed exactly as it had on 2026-09-10, so `scripts/antigravity.cjs` now appends it and a test checks for it.
- Antigravity eval driver: the app opens no DevTools port unless started with `--remote-debugging-port=1405`, and its UI server port changes on every launch (1407 on 2026-09-10, 29065 on 2026-09-11); `scripts/antigravity/drive.cjs` reads the origin from the page (stepping back out of an error page) instead of assuming a port.

### Added (2026-09-14)
- Fifteen activation prompts for the five skills the set never measured: `bk-plan`, `bk-close`, `bk-audit`, `bk-next` had none at all and `bk-test` appeared only as an alternative on someone else's negative. Two positives, one English one Vietnamese, and one negative each, per spec §11; the set goes from sixty to seventy-five and Phase 1's sixty are untouched so the baseline still compares. Two of the new negatives are false-activation controls that expect `none` — a Postgres query to optimise and a plain file read — since the kit has no `bk-db` and the profile it runs in carries skills that do.
- `tests/evals.test.cjs` gains the invariant that would have caught the gap: every skill that exists must carry at least two positive prompts. Proven non-vacuous by removing `bk-next`'s two and watching it fail. The `--per-intent` test went red with the larger set and was corrected from six intents to eleven; `sample()` itself did not change.

### Changed (2026-09-14)
- Question 12 of the D5 batch is narrowed by the owner: `bk-design` may be created and `frontend-design` ported without waiting for the §5.2 inventory to be declared complete. The condition still holds for every other skill. Recorded at the source with the reasoning, not only in the plan.

### Fixed (code audit, 2026-09-13)
- `record-guardrail.cjs` could not do the one thing spec §8 asks of it. Nothing creates the session store in v2 — the stack-profile hook that used to was deleted with the rule layer, and the session-start bootstrap writes nothing by design — so the exact command `bk-ship/SKILL.md:13` and `host-tools.md:17` tell the model to run (`--command "<cmd>" --exit <code>`, no `--session`) exited 1 with a message pointing at that deleted hook. Proven by running it in an empty state directory. The recorder now opens its own file when none exists, one per directory per day, and prunes older ones. A test in the suite had been asserting the broken behaviour; it is replaced, and the replacement says why.
- `bin/bearingkit.cjs` dispatched `constructor`, `toString` and every other name on `Object.prototype` as if it were a command: the CLI did nothing and exited 0, a silent success for a command that does not exist. `Object.hasOwn` now guards the table, with a test.
- `bearingkit doctor` ignored `--dest`, which `antigravity install` accepts: a copy installed anywhere else read as absent, and the repair line doctor printed would have installed a second copy at the default location instead of refreshing the live one. Doctor now takes `--dest` and names it in the repair line.
- The Antigravity copy writes its marker before the payload rather than after. An install interrupted part way — a file locked while the host is running, the reachable case on Windows — used to leave a directory the next install refused to touch because it could no longer recognise it as its own.

### Removed
- `scripts/install.cjs` with its junctions, settings merges, backups and uninstall; `adapters/`; the `stack-profile` hook and the host payload adapters; the path-scoped rule layer; `core/mcp.json` (context7 is documented per host, never installed). Tests of the removed pieces went with them (57 tests became 44, with four new files for manifests, agents, the hook and the Antigravity copy).

### Added
- `bearingkit doctor` (`scripts/doctor.cjs`, 80 lines): the read-only half of the install decision the owner took on 2026-09-12 (A + B′, `docs/specs/2026-09-12-install-council.md` §6–7). It reads the daily profile — the Antigravity copy under `~/.gemini` — and reports six things: the copy exists, its marker names this checkout, its rule still carries the protocol, the host note and the kit root, it carries the three scripts the skills call, its `skills/` matches this checkout byte for byte, and `hooks/session-start.cjs` still prints the protocol and the kit root. A mismatch prints the command that repairs it; doctor never runs it. **It writes nothing**: `tests/doctor.test.cjs` runs the command in a home of its own and compares the tree — every path, size, mtime and content hash — before and after, on a healthy copy, on a broken one and on a profile where the kit was never installed; that assertion was seen failing against a doctor deliberately made to write one byte. The two states §6 names as the measure are reconstructed as tests: a copy that dropped the host note (the state `3d7b4eb` shipped) and a copy older than the repository's `skills/`. The rule assertions and the throwaway-kit fixture are shared with `tests/antigravity-install.test.cjs` (`tests/fixtures/fake-kit.cjs`) rather than written twice. **One check from §6 is not implemented:** doctor does not shell out to `claude plugin list` / `validate`, because booting a host binary cannot be shown to write nothing and the owner's invariant outranks the check; the listing is reported as `skip` with the command to run, never as `ok`.
- `LICENSE`: MIT text, `Copyright (c) 2026 tuyenht` — the copyright line the owner set 2026-09-12 (`docs/specs/2026-09-12-d5-owner-questions.md`). `package.json` already declared `"license": "MIT"` and reserved the file in its `files` array; `NOTICE`'s opening line now points at `LICENSE` alongside `package.json`. No Apache-2.0 text is vendored yet (`upstream/sources.json` shows every Apache-2.0 source still at an empty `derived` map), so no new NOTICE entry is owed by this change.
- `README.md`, `docs/hosts.md` (install, bootstrap and acceptance status per host), `.claude-plugin/marketplace.json`, `scripts/antigravity.cjs` (`bearingkit antigravity install|uninstall`), `evals/activation/acceptance.jsonl`, the v2 spec, `docs/plans/2026-09-11-v2-restructure.md` and `docs/plans/2026-09-11-content-program.md` (inventory, per-skill sprints, stack files, release gate).
- Superpowers 5.1.0 (`f2cbfbe`, MIT) absorbed, the first mandatory source of Phase 2: `bk-spec/references/brainstorming.md`, `bk-plan/references/writing-plans.md`, `bk-build/references/executing.md`, `bk-test/references/tdd.md`, `bk-debug/references/systematic-debugging.md`, `bk-review/references/code-review-exchange.md`, `bk-ship/references/finishing.md`, `bk-protocol/references/meta-routing.md`; each SKILL.md cites its file under Read first (bodies grow by one line). `NOTICE` created at the root with the source's MIT notice; `upstream/sources.json` gains the derived map and ten more tracked files. Matrix row 1 moves to absorbed. Fixed context re-measured on Claude Code 2.1.268 (`claude -p`, first-turn input total, isolated profile): 43,817 before the port, 43,821 after, 43,823 with the new `references/` dirs hidden, so references cost nothing until read.
- `tests/skills.test.cjs`: two static checks taken from writing-skills, to move into `doctor` later: a skill body stays within 100 lines, cites only reference files that exist, and every `references/` file is cited (no BOM anywhere); a references file that says it is adapted from upstream has a derived entry in `upstream/sources.json` and points at `NOTICE`. Both checks were seen failing on an orphan file and on a dead citation before they were kept.
- Coverage matrix rows 13–39 for the owner's repository list (2026-09-11): four sources to absorb, eight references and opt-in integrations, seven hosts or tools recorded as host candidates or ideas, eight exclusions with the owner's reasons; license, archived flag, last push and stars read from the GitHub API on that day. `upstream/sources.json` records the HEAD sha of every source the kit will read (15 new entries, derived maps empty). Content backlog gains the follow-up group.

### Added
- `upstream/sources.json`: provenance of the two sources verified so far (Superpowers 5.1.0, the official plugins repository at its 2026-09-10 commit) with the tracked files; derived maps fill in as Phase 2 ports substance. The official repository is cached under the gitignored `_build/upstream/`.
- `docs/specs/2026-09-10-coverage-matrix.md`: one row per source the kit replaces or absorbs (Superpowers, the official plugins, spec-kit, ClaudeKit, Spartan, context7, Skillmark, fullstack-dev-skills, vercel agent-skills, document-skills, the owner's previous kit, Antigravity docs), with status and the measurement each "better" claim rests on; rows for the owner's remaining repositories to follow.
- `core/AGENTS.md`: the protocol (autonomy gate, router with intent table, evidence rules, council, definition of done, hot paths, host notes), 53 lines. The router says to invoke the matching skill before reading or searching code; without that sentence the model explored first and never invoked.
- `bk-protocol` hidden reference skill with gate patterns, personas, host tool map, evidence and council formats, RBA-lite, correction cues, the two-block handoff template.
- Ten protocol skills: `bk-next`, `bk-spec`, `bk-audit`, `bk-plan`, `bk-build`, `bk-test`, `bk-debug`, `bk-review`, `bk-ship`, `bk-close`. Frontmatter values are quoted (strict YAML; Antigravity dropped bare values with `: `), guarded by `tests/skills.test.cjs`.
- `scripts/detect-stack.cjs`: stack profile from manifests (Node, PHP, Python, Gradle, CMake, .NET, Go, Rust) with guardrail commands, hot-path globs, version card and PATH parity check.
- Session state store (`core/hooks/lib/state.cjs`), host payload adapters for Claude Code and Antigravity (`core/hooks/lib/host.cjs`), and the `stack-profile` hook that injects at most 120 tokens only when the session state changed, re-arms after compaction and no-ops inside subagents. The injected block closes with `[/bearingkit]` so a terse request after it is not read as context.
- `scripts/record-guardrail.cjs`: the writer for guardrail runs and independent reviews that the push gate reads.
- Activation eval set (60 prompts, six intents, two negatives per intent, English and Vietnamese) with a runner for Claude Code (`claude -p` stream parsing, `expect` alternatives `a|b`, an equivalence map for baseline runs against another setup, `--intent`/`--id`/`--per-intent` filters where `--per-intent` takes a spread per intent, quota read from the stream with a stop at 90% of the five-hour window) and a checklist for Antigravity. `evals/fixtures/sample-app` is staged in a directory whose ancestors carry no memory files (beside the repository by default; throwaway git history; `--stage-only` prints the path) and used as the working directory, so prompts have something to point at and neither the repository's own `CLAUDE.md` nor a daily profile under the home directory loads through the ancestor chain; the runner refuses to run otherwise. The staged copy is reset to its staging commit before every prompt, since sessions edit and even commit files.
- Adapters: Claude hook registrations, model map, plugin manifest; Antigravity plugin manifest and hook template (named-hook wrapper, one `PreInvocation` handler); `core/mcp.json` (context7); `core/rules/security-baseline.md`. On Antigravity the install is one real directory under `~/.gemini/config/plugins/` (the host's scanner does not follow junctions; a later `install` refreshes the copy; `--antigravity-link` for experiments); no registry file is written; the hook command is relative and points at a generated launcher inside the plugin, because the host resolves command tokens against the plugin directory.
- `evals/fixtures/sample-app` gained `src/lib/cache.ts`, `src/app/api/invoices/route.ts`, `src/components/header.tsx` and `src/app/signup/page.tsx` (2026-09-11), so every small-change prompt points at something the fixture holds; `sm-en-04` had asked for a log message that did not exist.
- `bin/bearingkit.cjs install --dev <repo>` for both hosts with backups scoped to the hosts a run touches, idempotent settings merges, a secrets-only deny list, `--config-dir` for an isolated Claude profile, `--dry-run`, and `uninstall` that removes exactly what was added.
